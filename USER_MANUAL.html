1. Glossary & Abbreviations

This simulator models advanced telecommunications architecture. Here are the core acronyms used in the system:

Abbreviation Full Form Explanation in the Simulator
MEC Multi-Access Edge Computing Moving server resources out of the central cloud and putting them physically closer to the user (e.g., in a local cell tower or ISP facility) to achieve ultra-low latency.
NFV Network Function Virtualization Replacing physical hardware routers and load balancers with software running on standard servers. Allows the Orchestrator to instantly "spin up" or reroute traffic via software.
VNF Virtual Network Function A specific software application running in the NFV architecture. In our app, the Edge Nodes acting as caching video servers are VNFs.
VNFM VNF Manager / Orchestrator The brain of the system. It monitors the health (latency/status) of all VNFs and decides which node the user should connect to.
DASH Dynamic Adaptive Streaming over HTTP The video streaming protocol used. The video is chopped into tiny 2-second segments.
ABR Adaptive Bitrate An algorithm in the video player that continuously calculates network speed and decides whether to fetch a High-Quality (4K) or Low-Quality (720p) segment next.

2. What is Actually Happening? (The Architecture)

When you press "Play" on the video, a complex sequence of decisions is made in milliseconds. Here is the step-by-step scientific breakdown of the data stream:

1. The Origin Server (Cloud)

The Origin Server is located in a distant centralized cloud data center. It holds the "master" copy of the 4K video. Because it is physically far away, the latency is very high (~150ms delay). Streaming 4K directly from here causes buffering.

2. The Edge Nodes (MEC)

Edge Node 1 and Edge Node 2 are localized servers situated near the user's city. They act as "proxies" or caches. When a user requests a video segment, they fetch it from the Origin, cache it, and deliver it to the user with ultra-low latency (~5ms to 15ms delay).

3. The Orchestrator (VNFM)

The Orchestrator acts as a load-balancer. Every 2 seconds, it pings the Edge Nodes. If Edge Node 1 catches on fire (Outage) or gets congested (Degraded), the Orchestrator instantly updates its routing table and instructs the Client to fetch the next video segment from Edge Node 2.

3. Telemetry & Live Stats (What the numbers mean)

The dashboard on the right side provides real-time analytics of both the video player's ABR algorithm and the advanced MEC Engine. Here is a comprehensive breakdown of all parameters:

Standard Telemetry

  • Resolution & Bitrate: If the network is healthy, the player requests 1080p or 4K. If the network degrades, it drops to 720p or 480p to prevent buffering.
  • Buffer Health (Seconds): Shows how many seconds of video are pre-loaded in memory. Healthy: 10-15 seconds. Critical: < 3 seconds.
  • Throughput / Bandwidth Utilization: The literal download speed (kbps) the browser is achieving. MEC nodes provide high throughput; Origin servers provide lower throughput due to distance.
  • Stalls & Dropped Frames: A "stall" means the video froze because the Buffer Health hit 0.0s. "Dropped frames" happen when the device CPU struggles or data arrives corrupted.
  • Segment Download Time: How long it takes to download one 2-second chunk of video. Must remain under 2 seconds to avoid stalls.
  • Quality Switches: The number of times the video jumped up or down in resolution. A good connection minimizes unnecessary quality switching.

Network Quality Metrics

  • RTT (Round Trip Time): The total time (in milliseconds) it takes for a data packet to travel from the client to the server and back. Lower RTT = Better Streaming.
  • Jitter: The variance or fluctuation in latency over time. High jitter causes unpredictable buffer drains.
  • Packet Loss: The percentage of data packets that get lost in transit and must be re-requested, heavily impacting throughput.
  • Network Cost: A simulated value representing the financial or bandwidth penalty of streaming from the distant Origin Server vs. the cheap local Edge Node.

MEC FMDASH+ Engine (Advanced NFV)

  • Shannon Entropy (H): A mathematical measure of unpredictability in the network. If the network is fluctuating wildly (high jitter), entropy increases, and the MEC Engine switches to a more conservative streaming profile.
  • Traceback Window (k): The number of previous video segments the AI is analyzing to predict future network conditions.
  • Smoothed Bandwidth: The rolling average of throughput, ignoring sudden, temporary spikes or dips (using exponential smoothing).
  • MEC ABR Decision: The maximum video bitrate the Edge Node recommends the client to fetch, calculated using Fuzzy Logic.
  • Fuzzy BW & Fuzzy BUF: Real-time Fuzzy Logic categorizations. The engine constantly evaluates if Bandwidth (BW) and Buffer (BUF) are in a 'Low', 'Medium', or 'High' state, visually represented by the colored indicator bars.
  • Edge Node CPU & Memory: Simulates the hardware strain on the local VNF container.
  • Transcoding Latency: The time taken by the Edge Node to process and deliver the video segment payload.

4. How to use the Demo Control Panel

Use the bottom-left panel to inject chaos into the network and watch how the Orchestrator and Video Player respond.

✅ Good Edge

Action: Sets Edge 1 to 5ms and Edge 2 to 15ms.
What happens: The Orchestrator routes you to Edge 1. You will see the Bitrate graph climb to maximum quality. Buffer health stays completely stable.

🟡 Degraded Edge

Action: Simulates a massive traffic spike on Edge 1, pushing its latency up to 80ms.
What happens: The Orchestrator realizes Edge 1 is becoming slow. It dynamically fails over to Edge 2 (which is still at 15ms). The video does not buffer because the NFV switch happens seamlessly.

🔴 Edge Outage

Action: Utterly destroys Edge 1 (simulating a power failure).
What happens: You will see a ✕ LINK DEAD indicator in the topology. The client's current segment download fails, throwing an error. The player immediately asks the Orchestrator for a backup route, and reconnects to Edge 2. The Buffer Health graph will likely take a massive dip during the recovery time!

🔵 Direct Only (Bypass MEC)

Action: Disables edge computing entirely. Forces the player to fetch from the Origin.
What happens: Latency jumps to 150ms+. You will visibly see the Throughput crash and the Buffer Health drain rapidly. The ABR algorithm will severely downgrade the video quality to survive.

🔄 Restore All

Action: Resets all simulated disasters. Revives dead nodes and removes artificial latency.
What happens: The network heals, returning to optimal 5ms MEC streaming.
